# 生产与演示双线：操作与验收

本轮共用业务核心，运行环境由启动参数固定。`production`、`demo`、`integration` 的账户、数据库、身份映射、网关账本、密钥和备份分别保存。端口和 Windows 维护步骤见 [部署说明](DUAL_TRACK_DEPLOY.md)。本文件不是案件授权、规则发布意见或真实发送验收收据。

## 视频第二案例：必须展示人工否决

使用 `demo` 环境创建新的 `human_veto` 合成案例。管理员先在“本地用户”建立技术复核、法学复核、审批三个独立账户。创建场景只写入材料和补充合成线索；不会预先写入通过、批准或否决决定。每次录制重新创建案例即可获得干净状态，旧案例和决定继续保留。

案件操作人员在披露页核对处理结果并执行初检。风险页同时展示初检结果和“待专业复核”，因此旁白应说“当前自动检查未发现阻断项，仍需人工专业复核”，不能说“系统已经证明安全”。如果运行四类攻击，应展开一类的输入范围、协议版本、请求摘要哈希、证据和结果，再让观众看到其他三类的状态。离线结果必须保留“模拟结果”标识；`未运行`、`不确定`、`检出`与有效检验后的`未突破`不能混讲为通过。

技术人员登录后，打开该案例的补充合成线索，勾选证据，输入问题说明并提交。此时立即展示顶部“人工复核暂停”、当前批准已撤销、发送不可用。可用的解说是：“自动检查依据的是当前请求及设定的测试范围；技术复核补充了组合线索，认为仍有识别风险，因此先暂停外发，交由法学人员判断。”提交动作调用生产共用的 `review-issues` 接口，不是录像脚本直接改状态。

切换到法学复核账户，核对原事实、补充线索和未解决事项，选择适用的复核条件与依据，填写事实前提、权限判断、外部处理条件、最小化措施、最终依据及适用边界，选择“否决本次请求”。演示依据是明确标注的项目演示控制项，不假装已发布法源。提交后展示“已否决”、具名复核人、理由、时间和历史事件，并实际确认批准、发送和重新检验无法使原请求继续发送。旁白可说：“初检结果保留，但专业复核发现当前请求不满足处理条件，法学人员否决本次请求。该决定已经阻止外发，并且保留完整审计记录。”

如继续展示整改，创建关联原任务的后继任务，调整披露后重新检验。未解决事项自动继承；直接另建任务也无法绕过。法学人员必须逐项选择已解决事项并填写解决依据，之后才可能由审批人批准新的完整请求。法学“允许处理”仅解除这一项复核限制。同案其他旧批准在问题提出时已撤销，问题解决后不会自动恢复。

当 worker 已在事务中转入 `sending` 时，发送前否决边界已经过去。界面和接口应明确拒绝“已阻止发送”的表述，随后核对网关记录；超时保留“结果不明”，不能重新发送来试探结果。

## 其余三条可重复路径

`success` 用于完整流程：材料、事实、披露、初检、法学允许、审批人批准、模拟调用、结果回链和人工核对。`linkage` 用于系统检出组合风险，解释自动阻断。`stop` 用于材料不足停止。四条路径共用工作台、复核接口和状态机。

披露页只展示有区别的可选输出，重复候选合并展示，淘汰理由保留可查。姓名和单位保持一致替换；“原精度”描述日期、金额等业务信息的精度，并不表示外发原始身份。没有规则依据时不能为了镜头效果降低日期或金额精度。任务切换用于说明事实摘要与本地时间线等任务的必要信息不同，不要求把所有候选逐一点击。

完整请求快照应展开目标、模型、实际消息正文、材料版本、规则版本和请求哈希。只有披露正文进入模型请求，原文与身份映射留在边侧。调整正文、材料、规则或相关依据会使旧批准失效。

`integration` 使用同一批内置合成场景和真实模型配置。网关独立重建登记材料可产生的输出，核对正文结构、固定提示词及合成清单，不接受任意上传、自由编辑正文或生产许可。实际模型、目标、返回、耗时和版本保存在运行记录中。此环境需要真实密钥及可达服务；失败后如改用 `demo`，录制必须展示环境和结果来源的变化。

## 正式单次放行的准备顺序

生产常规外发与首案验收共用同一证据、复核、审批和网关消费链，但策略范围不同。首案验收使用兼容策略 `scope_kind=first_acceptance`，固定为 `LA-001 × R_fact_summary × D_DeepSeek_official_API`，仅用于计划中的首宗真实案件验收。常规规则包可以按 `domain + purpose + recipient=实际服务商档案ID` 覆盖同一案由中符合范围的任务，也可以精确限定单个 `case_id`；两种规则范围都必须显式声明，不能用通配符，也不把 `primary` 当作任意服务商别名。规则包适用范围只决定哪些请求可进入后续门禁，不授予发送权。常规生产请求使用 `scope_kind=request`：管理员对每个新的当前请求调用 `POST /api/v1/tasks/{task_id}/formal-release/policy`，提交当前 `request_hash`（可省略 `scope_kind`，默认为 `request`）；服务端从已保存任务和获核验构建中推导具体案件编号、主服务商、目标与模型。因而可复用的 domain 规则仍对应每个具体案件、每个新请求的独立一次性策略。每份策略只允许一次发送，不能用一份策略覆盖同案后续请求，也不能将旧请求的审批或许可移到新请求。该接口拒绝非管理员、过期请求哈希及运行库导出哈希与构建清单不符的情况。常规策略要求规则运行库已经审查、发布并激活，且激活记录的 `artifact_sha256` 与已核验构建的 `runtime_pack_hash` 精确一致；缺失或不匹配时必须先完成规则发布、激活和构建核验，不能用首案策略放宽。

1. 固定提交、镜像、前端、wheel、锁文件及获准 Runtime Pack，生成真实构建清单。API、worker、gateway 都须加载同一份已核验清单。客户机器先完成隔离与备份检查。生产缺省关闭，代码发布本身不授权发送。
2. 在生产环境创建正式案件并登记 `reference_code=LA-001`，上传获准材料并完成人工事实校核。配置经核验的 DeepSeek 官方 API 档案、模型、地址和单一主槽。不得把测试夹具的服务商字段、法源或批准人复制为正式证据。
3. 通过现有法学证据流程登记真实材料授权、法源及规则发布意见。生产专用 `/api/v1/formal-release/evidence` 接收受控证据文件，`/formal-release/receipts` 接收对应 G 表收据；签署角色与当前具名账户绑定。首案验收由管理员安装一次 LA-001 首案策略；后续常规请求按上文为每个当前请求安装独立 request 策略。策略始终从 `blocked` 开始，不能代表证据或批准。
4. 冻结完整请求，运行正式组合判断和冻结的四类攻击协议。技术人员通过 `/formal-release/isolation` 登记该构建与该请求的隔离证据，由法学人员通过 `/formal-release/isolation/{id}/confirm` 引用有效确认收据。`/tasks/{id}/formal-release/check` 返回实际缺口；此接口不会自动签署或补齐证据。
5. 全部证据、构建、目标和版本匹配后，由法学人员完成当前请求复核，审批人具名批准。系统签发有期限的一次性许可，入队时预留，网关在真实调用前持久化唯一消费记录。发送开始后超时或失联只能查询原记录，不能补发、恢复额度或换接收方。成功后完成摘要、主体、数字、引用、争议状态及来源回链的人工核对，并留存账本。

浏览器中的正式请求在风险页提供“正式放行证据与人工收据”。其只读上下文由后端从当前请求、已核验构建和实际服务商推导；条件缺失时显示具体阻断，不生成占位许可。登记人员先选择法/技模板并上传受控原件；相应角色再选择原件与附件、明确结论和有效期。表单默认待核，不自动勾选通过。法01须逐项选择采纳事实，法02须核对当前请求的授权声明与组织授权证据，法03和法04须分别登记；法08、法09、法10须绑定对应的技04、技05、技06。技术人员可导入实际测量形成的隔离收据，法学人员选择本人签署的同请求有效 G8 收据后确认。最后使用“手动检查当前放行门并刷新任务”核对余下缺口，之后仍须独立审批。收据历史和撤销原因保留可查。

规则发布、真实材料授权、服务商条件、有效风险证据和具名决定由相应责任人提供。研发人员不得代填通过结论。没有这些证据时，生产首版保持未验收，即使合成场景或模拟供应商测试全部成功。

## 固定版本交付包

`scripts/package_delivery.py` 将已经构建的 Docker-save 镜像归档、wheel、构建清单、锁文件、镜像绑定的依赖与许可证清单、维护脚本和说明组装为 ZIP。它核对镜像配置的 SHA-256、wheel 与锁文件是否匹配构建清单，拒绝覆盖已有包。它不会构建或下载镜像，不会激活策略，也不会生成虚假的验收结果。

依赖清单格式为 `{"runtime_image_id":"sha256:…","components":[{"name":"组件","version":"实际版本","license":"许可证标识或随包声明位置"}]}`。应从实际交付镜像和前端依赖生成，保留上游二进制与传递依赖许可，不能用一份手写示例代替完整清单。运行镜像与路由隔离镜像都须预先包含在 `docker image save` 归档中；Windows 加载镜像后使用包中 `delivery.json` 的固定镜像 ID。模型权重单独登记来源、版本、许可证和校验值，不在启动时静默下载。

```text
python scripts/package_delivery.py --profile production --images <images.tar> \
  --runtime-image <sha256:image-id> --route-image <sha256:route-image-id> \
  --manifest <release-build.json> --wheel <lexaegis.whl> \
  --dependencies <dependencies.json> --output <delivery.zip>
```

## 验收证据与未完成条件

代码回归覆盖技术与法学权限分离、管理员不能代行、负面复核、幂等决定、同案继承、旧批准撤销、worker 并发边界、重启恢复、环境混用拒绝、合成正文校验以及升级失效。具体执行结果写入 [VALIDATION.md](VALIDATION.md)，以实际运行记录为准。

以下项目不能用本地测试替代：Windows 干净机器安装及 Docker Desktop 的端口/ACL/升级回滚实测；合成材料的真实模型与红队联调；固定镜像、完整依赖许可证及正式构建清单的交付；一宗获准真实案件的一次实际调用、返回、来源回链、具名最终核对和完整备份恢复。验收记录必须附目标机器、环境、提交、构建与请求身份，禁止将占位或未执行项填为通过。
