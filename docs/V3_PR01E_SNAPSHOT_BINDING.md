# V3 待发送许可与当前证据快照绑定

正式放行在排队和 worker 发送前，除重新评估全部既有门禁外，还比较持久化一次性许可的 `gate_snapshot_hash` 与当前评估快照哈希。两者不一致时拒绝排队或发送；排队后在 worker 发送前发现不一致时，现有错误处理撤销未消费许可，网关和 provider 均不调用。审批阶段仍按原流程创建许可，已经 claimed 的历史不在此逻辑中重写。

快照保留用于撤销反查的保守 `evidence_receipt_ids`，另新增 `validated_receipt_ids` 纳入哈希。后者是本次通过检查的收据集合；这样即便另有同门有效收据使门禁仍通过，一份请求级收据到期也会改变快照。增加另一份通过检查的收据同样会触发重新审批，这是有意的保守行为。

先前版本的快照算法没有 `validated_receipt_ids`，旧许可不会自动迁移到新哈希。未发送旧请求会在下一次排队/发送前的校验中被拦截；要继续，须撤销旧许可并按现行流程重新评估和批准。此检查不追溯修改已发送记录，也不接入跨案件分层证明或真实签署服务。测试使用合成受控证据、本地网关和 provider stub；正式部署及真实审批仍需单独验证。
