# V3 请求级策略与具名审批

`LEX_AUTO_REQUEST_POLICY=1` 时，生产正式云端请求可在具名审批事务内，从当前冻结请求和已发布、已激活、与已验证构建哈希一致的 request-scope 运行库推导一条精确请求策略。新策略最初仍为 `blocked`，目标、模型、接收方、主备槽和请求哈希均由服务端推导；创建者必须是具有当前请求有效 G10 角色动作的具名审批人，且该动作的记录账户须与当前登录审批账户一致。现有手动安装接口仍严格要求管理员，首案策略路径保持原状。

系统随后仍执行原有全部 G 门、受控证据原件、具名角色动作、隔离证据和当前版本检查；仅全部满足才在同一事务签发一次性许可。事务内使用保存点，任何后续失败即撤销临时策略、审批与许可，即使调用者在外层事务捕获异常也不留下半成品。审核结果预览中的 `auto_policy_candidate` 只表示可以尝试服务端核验，不表示门禁通过或获得发送权。

默认关闭该开关；关闭时沿用管理员手动安装策略。此阶段仍使用现有逐请求证据，不复用离线影子证明；没有解除产品级能力状态，也不代表真实法学签署、外部服务调用或生产验收。已发布运行库、真实构建、身份和证据必须独立具备。
