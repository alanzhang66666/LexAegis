# 案隐盾：十案上云路径设计 v0.1

日期：2026-09-14。适用对象：团队确认均已公开的 LA-001—005、工伤样例 1—5；用途限**劳动争议裁判文书事实保真摘要**。团队不拿案例训练模型，原文解析、事实确认、身份映射、风险评估与人工审核均在本地。云端若启用，只接收经批准的最小事实卡进行一次推理。本文是实施设计，**不是十案发送授权**；本次未调用云 API。

## 一页读懂

`公开文书 → 本地核版本/抽事实 → 本地删减与角色替换 → 审核完整请求 → 受控网关发一份事实卡 → 本地逐句回链验收`

云端不接收文书附件、数据库下载副本、参考摘要、身份映射、原始证据、案号、公开链接、案件稳定编号、原文锚点或内部审批记录。云端返回的摘要仍是待核稿，不能自动变成“法院已认定”。只要事实卡仍可与公开文书组合定位个人，就继续按个人信息处理，不能因用了 `[[LEX:P0001]]` 便宣称匿名。

公开裁判文书使“合理范围内处理已合法公开信息”成为可能；个人明确拒绝、重大影响、医疗健康等敏感信息仍须单独审查。API 推理若涉及委托处理、敏感信息，应审查接收方条款并做事前个人信息保护影响评估。[《个人信息保护法》第 6、13、21、27—30、55—56、73 条](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)

## 任务与请求契约

当前系统只有 `fact_summary` 一个可选云端任务，不能把十案当作现有“核对加班”规则的适用例。先在本地定义三个**业务子目的**，由法学审核字段必要性与输出标准；技术再决定是在同一 `fact_summary` 规则包中按子目的选择，还是发布新任务版本。旧任务的批准不能继承到新子目的。[任务注册代码](https://github.com/Hanyuan9766/LexAegis/blob/5de41136ee1c12942a299e4f44c4c8afb2a8a258/lexaegis/task_engine.py)

| 本地子目的 | 适用案 | 云端只负责 | 本地必须先完成 |
| --- | --- | --- | --- |
| R：劳动关系经过与争议状态 | LA-001—004 | 根据已确认命题写关系和争议经过，不判断新证据真伪 | 多主体、起止时间、主张/认定、证据归属；冲突并列或隔离 |
| W：欠薪、解除与经济补偿经过 | LA-005 | 概述争议焦点、双方理由、法院认定及结果；首版**不算金额、不判断期限** | 核欠薪与解除的事实锚点；待岗年份倒置仅本地标为冲突，不让模型猜改 |
| I：工伤待遇争议经过 | 工伤样例 1—5 | 在确有必要时概述关系、责任与待遇阶段；不读病历全文 | 先区分劳动关系、工伤责任、医疗/伤残事实；核医疗信息是否真的需要上云 |

现有[云端 wire 契约](https://github.com/Hanyuan9766/LexAegis/blob/5de41136ee1c12942a299e4f44c4c8afb2a8a258/lexaegis/cloud.py)只允许 `contract_version`、`task`、`facts`；每个 fact 只含 `id/text/field`。本地的来源锚点、真名映射、必要性理由、冲突记录和审批决策留在本地，不新增到 wire。服务层将系统提示词和该 JSON 组装为完整请求，审批必须绑定**完整请求哈希、目标端点、模型、参数、规则及材料版本**。[现行请求构造](https://github.com/Hanyuan9766/LexAegis/blob/5de41136ee1c12942a299e4f44c4c8afb2a8a258/lexaegis/service.py)

### LA-005 首个本地待审事实卡草样

以下是按已解析文书的事实设计的**结构示意**，仅供在系统内创建候选；`F1—F5` 须换成系统生成的真实事实 ID，逐项回链并审查后才可能形成请求。本节本身不作为可发送文件。

```json
{
  "contract_version": 2,
  "task": {"id": "fact_summary", "version": "2.0"},
  "facts": [
    {"id": "F1", "field": "relation", "text": "劳动者[[LEX:P0001]]与用人单位[[LEX:P0002]]之间的劳动关系已获一审确认，双方对该项未提出异议。"},
    {"id": "F2", "field": "event", "text": "一审法院认定用人单位未及时足额支付劳动报酬。"},
    {"id": "F3", "field": "event", "text": "劳动者以未足额支付劳动报酬为由解除劳动合同并请求经济补偿。"},
    {"id": "F4", "field": "event", "text": "用人单位上诉主张劳动者系主动解除，欠薪源于经营困难，因而不应支付经济补偿；劳动者不同意。"},
    {"id": "F5", "field": "event", "text": "二审法院驳回该上诉，维持一审关于经济补偿的判决。"}
  ]
}
```

本地回链草案：F1→解析文书 P19；F2/F3→P20；F4→P11—P12；F5→P25—P27。段位只是本次解析文本的位置，必须由人对照正式公开版本复核。P16 的待岗通知日期倒置、精确工资与经济补偿金额、法院/地域/案号、公司职务及原文参考摘要均不进入这一狭义子目的。若要求金额、工龄或待岗先后关系，**另建候选和任务规则，重新评估**；不能在已批准请求上临时加字段。正式请求还含系统提示词、模型、端点、参数和授权目标，本 JSON 不是完整批准对象。

## 十案的推进顺序

| 批次 | 案例 | 本地先验证 | 进入层 B 的额外条件 |
| --- | --- | --- | --- |
| 0：只做本地 | LA-002 | 日期冲突与一、二审来源回显 | 不让模型选定有争议的起点；来源链核准 |
| 1：事实卡候选 | LA-005 | 上述 W 子目的、年份冲突隔离、摘要逐句回链 | 层 B 登记冲突解决，W 规则发布与全门禁通过 |
| 2：主体关系 | LA-001、LA-003、LA-004 | 多主体不合并；LA-003 改错标注；证人/录音只本地 | R 规则和跨轮链接风险实测；第三人信息可控 |
| 3：工伤低精度尝试 | 工伤样例 1—3 | 金额核对；关系/责任分开；退休条件本地计算 | 数据库副本使用条件、敏感信息必要性与 I 规则另审 |
| 4：优先本地 | 工伤样例 4—5 | 精细诊断、住院与前案是否任务不可缺；条件项不当事实 | 若删减后仍能完成 I 子目的才重开；否则本地完成 |

**业务排序不等于发送许可。**若最终层 B 登记只允许 LA-001，就不能因为 LA-005 更容易摘要而先发 LA-005；也不应为了“先发一案”跳过 LA-001 的组合识别测试。批次 0—4 都可先做本地候选和模拟。

| Q：百炼北京地域 `qwen3.8-flash` | 优先做合成请求联调；真实案需全门禁 | 实际北京 Workspace/API Host/Key、Qwen 模型、合同及处理角色；确认推理日志/日志回流未开启、留存/审核访问/删除边界。百炼[协议](https://terms.alicdn.com/legal-agreement/terms/common_platform_service/20230728213935489/20230728213935489.html)承诺未经授权不以对话数据训练，但允许内容审核；[地域文档](https://help.aliyun.com/zh/model-studio/regions/)和[模型页](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)用于核端点与模型。 |
| D：DeepSeek 官方 `deepseek-v4-flash` | 若赛规仍要求指定模型，则作为**独立准入路径**；合成联调可先行 | 官方 `api.deepseek.com`、实际账号/合同与境内处理说明；确认该 API 账号的训练退出覆盖请求、已生效，核留存、人工访问和删除。DeepSeek[API 文档](https://api-docs.deepseek.com/zh-cn/)确认模型/端点；[用户协议第 4.3 条](https://cdn.deepseek.com/policies/zh-CN/deepseek-terms-of-use.html)载有可能训练及退出机制，不能凭团队“不训练”推定服务商不训练。 |

首个真实案选择 Q 或 D **其中一条**；先只批准一个目标，关闭自动备用。若赛规最终要求 D 的真实完整运行，Q 的成功记录不能替代 D；D 须另过同一套门禁。目标、模型、条款版本或训练开关变化使旧批准失效。百炼上的 DeepSeek 模型不算 D 路径，须另建服务商档案。不要把 API Key、案件 ID、真名或完整请求写入公开比赛截图。

## 七道发送门

| 门 | 通过证据 | 未通过动作 |
| --- | --- | --- |
| 1. 文书与用途 | 每案公开发布链接、取得版本、解析副本对应；工伤 DOC 如用北大法宝副本，核实际订阅条款；或改用独立公开原文。参考摘要与文书分层。 | 只本地整理或替换来源。平台[服务协议](https://login.pkulaw.com/Register/ShowClause)对第三方提供内容有限制，具体以实际合同为准。 |
| 2. 任务与规则 | `fact_summary` 的 R/W/I 子目的、字段必要性、允许精度、冲突处理、输出标准经审核并在运行库发布；`dispatch_allowed` 只在适用范围内为真。 | 保留草稿包与本地输出。 |
| 3. 处理依据与保密 | 每类主体/信息有合理范围判断；敏感健康、第三人、商业秘密分开审核；受托处理约定和实际影响评估留档。 | 删减、转本地或停案。 |
| 4. 单一接收方 | 目标档案 `reviewed` 且有效：合同/条款版本、签约主体全称、模型/端点/地区、训练、人工访问、留存、删除、转委托均有证据；仅目标主机获外联。 | 禁用该槽。不能以口头“默认合法”补空字段。 |
| 5. 最小事实卡 | 本地确认事实有独立来源锚点；主体全字段替换；无原文附件、参考答案、直接身份、组合定位线索或非必要精确值；删除后任务仍可完成。 | 修改候选；必要事实删光则 `blocked`。 |
| 6. 风险和隔离 | 对**最终完整请求与接收方历史**跑冻结的四类攻击、阳性对照与人工复核；结果须达到法学认可的 `resisted`，隔离与外联控制在目标环境实测。 | `uncertain`、`not_run`、失败均不算通过。当前工程基线不能代替此项。 |
| 7. 精确批准 | 有权审查人看到完整请求、事实必要性、残余风险、目标和保存条件；批准绑定哈希与依赖版本；发送前再验。 | 版本/目标/参数变更即失效，回到门 5。 |

网关发送时只允许已审目标，先记尝试，再发送。若请求超时、部分响应或是否抵达服务商不明，状态为 `unknown/possible disclosure`，**不盲重发、不自动换模型**；先查本地账本与服务商记录。回包后逐句核 `source_ids`、主体、主张/认定、否定、时间金额归属和缺口；错误结果留作待复核，不能直接用于对外文书。审计保存请求哈希、规则/模型/端点版本、批准人、发送状态与输出校核，不在普通日志重复存原文。

## 交付与验收顺序

1. **本地设计验收**：技术以合成材料实现单接收方、境内 allowlist、完整请求预览/哈希、日志最小化和失效/超时状态；LA-002 做来源冲突回显，LA-005 做上面的 W 候选。证明 `0` 次真实案 HTTP 请求。
2. **法学内容验收**：把十案层 B 冲突表合并为单一版本；R/W/I 的字段与输出标准落表；逐案记录公开版本、数据库副本条件、处理依据、保密和敏感必要性。AI 审核与有权自然人审核分别署明，不互相冒名。
3. **服务商与安全验收**：只给实际启用的一条路径建完整档案、实际影响评估、删除渠道；正式规则包、权重、四类攻击、隔离及目标环境控制均有真实证据。配置快照与条款版本绑定。
4. **首案受控运行**：在全部门禁通过后才选一案、一个子目的、一个 API、一个请求版本；人工批准后由网关发送一次，保存真实回包和逐句来源校核。若赛规要求 DeepSeek，再按 D 路径独立完成。
5. **扩至十案**：每案独立记录 `local_only / candidate / blocked / approved / disclosed / unknown / failed / complete`，未发与阻断计入总数；工伤案按敏感信息分支，不因第一案成功自动继承许可。

验收只报告实际证据：正式原文外发应为零；每次真实发送须能还原“哪个版本的事实、给了哪个接收方、谁批准、何时发送、返回是否完整、哪句由哪条本地事实支持”。设计通过、合成演示成功、工程攻击基线、法律可用性和真实云端成功各是不同状态。
