# 案隐盾：系统法学规则与验收标准

- 版本：v1.0
- 日期：2026-09-12
- 状态：规则内容定稿，供系统接入及自动验收使用。
- 适用范围：劳动争议裁判文书的本地事实整理、披露候选生成与结果校核。
- 工作口径：案例收集按既有安排继续；本文直接确定其余规则内容，不设置人工复核、双人标注、签署或再次讨论环节。
- 完成边界：规则内容完成与程序实现、真实运行是分别记录的状态。本文不把尚未运行的检查计为通过，也不生成实际不存在的账号、合同、材料权限或运行证据。

## 一、系统现在执行什么任务

### 1.1 固定任务

本期任务确定为：**依据已提供的劳动争议文书，整理主体关系、事件、陈述状态、日期金额和证据提及，生成具有来源依据的本地摘要及披露候选。**

| 项目 | 本期确定内容 |
| --- | --- |
| 任务类型 | `fact_summary` |
| 子目的 | `劳动争议文书事实保真整理` |
| 运行方式 | 本地解析、边侧抽取、本地整理；云端发送单独受接收方与运行条件约束 |
| 已有材料用途 | 劳动关系、欠薪解除、工伤待遇等材料用于检验事实整理能力 |
| 输出内容 | 结构化事实、带出处的摘要、缺失与冲突清单、披露候选及处理理由 |
| 输出不承担的任务 | 新案件裁判预测、独立认定劳动关系、自动计算赔偿、作出影响当事人权益的决定 |
| 加班字段 | 仅在明确的加班子任务中启用，不因某案出现“加班”二字就改变任务 |

本期摘要回答五个问题：谁与谁有关；发生或被主张发生了什么；谁主张、否认、承认或作出认定；相关日期金额分别属于什么事项；依据在哪里、哪些材料尚未提供。

### 1.2 输入分层

| 层 | 内容 | 使用规则 |
| --- | --- | --- |
| 文书层 | 提供的裁判文书正文、页码、段落、表格 | 作为事实和文书转述的来源 |
| 答案层 | 既有参考摘要、分类表、预期输出 | 用于对照，不混入待抽取的文书正文 |
| 材料目录层 | 实际收到的附件、文件哈希、版本和来源信息 | 用于判断某份证据是否真的在本次输入中 |
| 系统结果层 | 抽取候选、摘要、校核结果、失败记录 | 保留生成方式及版本，不反过来充当原文 |

文书中提到银行流水、考勤表或聊天记录，只能证明文书记载了这些材料，不能据此将附件状态设为“原件已提供”。

### 1.3 自动完成状态

本期采用下列目标状态，不创建人工待办：

| 状态 | 触发条件 | 系统行为 |
| --- | --- | --- |
| `complete` | 当前任务所需信息有来源，全部适用校核已执行且通过 | 输出本地整理结果，并显示来源与用途 |
| `partial` | 存在明确缺项或冲突，但仍能回答部分任务问题 | 输出有来源的部分及限制；不补齐未知结论 |
| `blocked` | 输入不可处理、无可靠来源、必要关系无法保留，或关键校核不能执行 | 停止生成相关最终结果，返回具体原因 |

争议本身不是程序错误。双方说法不同而系统准确并列时，可以完成“整理争议”的任务；如果任务要求确定唯一日期而来源不能支持，则该问题不能完成。

## 二、统一事实结构与字段规则

### 2.1 最小记录

一条记录表达一个能够独立核对的命题。以下字段定义已确定，具体接口支持情况见第十节。

| 字段 | 确定含义 |
| --- | --- |
| `case_id`、`document_id`、`document_version` | 案例、来源文件及版本；禁止仅靠文件名关联 |
| `fact_id`、`field` | 稳定事实编号及所属字段 |
| `quote`、`source_ids`、`source_location` | 支持该命题的摘录、来源块及页/段/表格位置 |
| `normalized_statement` | 便于整理的表述，与原文摘录分开保存 |
| `subject_ids`、`speaker_id` | 涉及主体与陈述者分别记录 |
| `statement_status` | `claimed`、`denied`、`admitted`、`court_found`、`document_recorded`、`not_stated`；未明确则 `unknown` |
| `negated`、`conflict_group` | 否定含义及冲突关联；冲突不能覆盖来源版本 |
| `evidence_presence` | 本次提供原件、提供复制件、仅文书提及、未记载，分别记录 |
| `necessity`、`transform`、`rule_id` | 对当前任务的必要性、处理动作及对应规则 |
| `condition_result` | `met`、`unmet`、`unknown`；未知不能自动改成满足 |
| `validation_status` | 记录实际运行的校核结果，不等同于人工作出的事实确认 |

`not_stated` 用于描述输入缺项，不生成“该事项不存在”的案件事实。`court_found` 只表示文书明确转述的法院认定，不表示系统独立认定。

### 2.2 必要性和处理动作

| 取值 | 执行含义 |
| --- | --- |
| `required` | 回答当前任务不可缺少；缺失时降为部分结果或停止对应问题 |
| `conditional` | 仅当明确条件成立时需要；条件不明时保留未知，不采用依赖该条件的结论 |
| `unnecessary` | 对当前任务没有作用，不进入摘要及披露候选 |
| `uncertain` | 无法确定是否必要，暂不进入可披露候选；不能自动等同于法律禁止 |
| `keep` | 保持信息精度，不代表允许外发 |
| `pseudonymize` | 一致替换身份字符串，保留角色及关系 |
| `generalize` | 在特定规则明确允许时降低精度；禁止作为所有字段的统一默认 |
| `delete` | 从当前摘要或披露候选中删除；不修改来源文书 |

### 2.3 通用字段矩阵

下表确定本地整理及候选文本的语义规则。真实来源文书保存在既有材料权限范围内；候选文本本身不取得发送权限。

| 规则ID | 字段 | 必要性及条件 | 最低保留内容 | 候选文本处理 | 缺项或冲突行为 |
| --- | --- | --- | --- | --- | --- |
| `local_entity` | `entity` 主体 | `required`：涉及本任务的主体 | 独立主体编号、角色、指代关系 | 姓名、机构登记名一致假名化；不同主体不得合并 | 身份对应不唯一时不合并，相关关系保留未确定 |
| `local_relation` | `relation` 关系 | `required`：任务涉及的关系 | 两端主体、关系类型、陈述者及陈述状态 | 替换主体名称，保留关系及其争议状态 | 分别保留不同说法，不输出系统自行认定 |
| `local_event` | `event` 事件 | `required`：影响摘要任务的事件 | 谁实施、做了什么、作用对象及来源 | 保留事件，去除无关身份线索 | 缺核心主体或动作时不生成完整肯定句 |
| `local_date` | `date` 日期 | `conditional`：涉及起止、通知、送达、期间、顺序或数值归属 | 原文已给出的精度、日期性质及对应事件 | 保留必要精度；不得一律截月或平移 | 不猜改年份；冲突日期并列并保留各自来源 |
| `local_amount` | `amount` 金额 | `conditional`：涉及请求、支付、认可、认定或金额争议 | 数额、单位、期间、款项性质、主体、程序阶段及陈述状态 | 保留上述关系；主体名称替换 | 不把请求额写成判决额，不静默计算出“应付额” |
| `local_evidence` | `evidence` 证据 | `conditional`：涉及主张依据或任务所需材料 | 名称、证明目的、文书如何提及、本次实际提供状态 | 保留必要描述，不输出整份原件 | 未提供就记未提供；不能把有名称当作证据内容已核验 |
| `local_stance` | `claim_stance` 对应陈述信息 | `required`：命题具有陈述归属 | 陈述者、主张/否认/承认/法院认定及否定含义 | 全部保留 | 状态未知时采用中性转述，不能提升为认定 |
| `local_holder` | `evidence_holder` | `conditional`：持有关系影响任务 | 谁持有，与谁提交、谁制作分别记录 | 主体假名化，保留关系 | 未知时写未记载，不从角色推定持有人 |

共同约束：主体归属、时间关系、数值关系、否定、争议状态和来源关系不可破坏。必要信息无法在这些约束下处理时，停止该项披露；不能通过删除必要关系制造“安全且合格”的空摘要。

### 2.4 特殊信息处理

| 对象 | 本期确定处理 |
| --- | --- |
| 身份证件号码、手机号、银行账号、详细住址 | 本期事实摘要不需要完整字符串，默认不进入摘要和披露候选；保留主体角色或证据类型即可 |
| 法官、书记员等姓名 | 当前任务无必要时从摘要候选省略；该动作标为项目最小化规则 |
| 唯一岗位、公开获奖、精确地点与罕见事件组合 | 联合检查可链接性；必要时降低非关键线索精度。无法维持任务效用与候选限制时，阻断该候选 |
| 医疗、工伤信息 | 只在该子任务需要时保留与争议有关的伤情、期间、等级或待遇关系；不整段复制病历、不加入无关既往病史 |
| 多公司、派遣、平台、关联用工 | 分别保留签约、管理、付款、投保等角色；不自动归并为单一“用人单位” |
| 国家秘密标识、明确保密限制或用途限制 | 不进入普通模型处理路径；限制性质或适用范围不明时，自动停止对应内容的处理 |
| “如存在账号”等条件检查项 | 记为检查条件，不作为该案已有账号的事实 |

这些是本项目的处理策略。具体信息是否受法定保护、实际处理依据是否存在，与字段必要性分别记录，不能从“应删除”反推某项信息一定属于法律禁止处理。

### 2.5 加班扩展规则

既有 V2 八条加班规则按以下口径接入，不自动扩展到一般摘要：

| 现有规则ID | 确定口径 |
| --- | --- |
| `overtime_date` | 任务明确需要核对具体加班日期时，保留原日历日；日性质未知不构成删除已知日期的理由 |
| `overtime_hours` | 保留已陈述的工时、期间、主张者与来源；未知时不反推小时数 |
| `overtime_wage_base` | 仅在基数本身属于争议或任务明确包含金额核对时纳入；普通加班经过摘要不默认需要基数 |
| `overtime_day_nature` | 保留已被材料支持的日性质；不能只按周末推定休息日，不能从缺少考勤推定正常出勤 |
| `overtime_claim_stance` | 保留主张、否认、认可和法院认定的区别；“持有证据”不属于陈述立场 |
| `overtime_evidence_holder` | 分别记录持有、提交、制作和文书提及，不相互替代 |
| `overtime_entity` | 独立主体一致替换，保留劳动者、各单位及第三人的不同角色 |
| `overtime_relation` | 保留关系类型及来源中的陈述状态；不因工资由某公司支付即认定劳动关系 |

本期不实现加班费法律计算。上述精度要求服务于材料保真；不能由举证责任条文直接推出向云端发送精确日期、金额的必要性。相关法源入口见第十一节。

## 三、G1–G5 的确定处理规则

| 条目 | 本版决定 | 系统执行结果 |
| --- | --- | --- |
| G1：清单与文书不是同一来源 | 将文书事实、独立事实记录和参考摘要分层；不存在文书锚点的内容不得伪造回链 | 有独立可追溯来源的记录使用自己的来源类型；无来源的只留在答案层，不进入文书事实输出 |
| G2：信息类型无法映射事实字段 | 信息类型是保护对象分类，事实字段是任务语义，必须分栏 | 证件号等作为主体属性或识别线索，不强行写成事件；一行含多个命题时拆分并保留原行ID |
| G3：边侧抽取属于草稿 | 原始抽取结果与通过自动校核的记录分开保存 | 子串命中仅通过来源形式检查；主体、状态及关系等适用检查缺失时，不标为完整验证 |
| G4：缺省删除导致空载荷 | 未明确必要性时不得进入披露候选；该结果属于项目保守控制 | 必要内容被删光则任务为 `blocked`，不能按“零泄露”计成功；来源材料不随候选删除 |
| G5：事件等字段仍带登记名 | 候选中涉及主体的所有字段统一替换，不只处理 `entity` | 日期、金额、事件、证据描述中的名称也要匹配同一主体映射；替换后重新查找残留 |

指南版本统一为 `G-2026-09-12-v1.0`。规则、来源、映射或输入版本变化后，旧结果保留为历史版本，受影响的结果自动重新校核。

## 四、未知、冲突和失败的自动处理

### 4.1 处理顺序

1. 检查材料可处理范围、文件版本及输入是否可解析；不满足时停止对应处理。
2. 分离文书、参考答案和附件目录，建立来源块及主体映射。
3. 提取命题，分别记录陈述者、对象、状态及来源。
4. 按任务与条件选择规则，生成本地摘要和披露候选。
5. 自动检查来源、主体关系、状态、数值、精度、直接标识及组合线索。
6. 返回 `complete`、`partial` 或 `blocked`，同时记录原因及实际执行的检查。

### 4.2 具体策略

| 情况 | 自动处置 | 允许输出 |
| --- | --- | --- |
| 原文日期或金额互相矛盾 | 分别保存并关联冲突组 | “材料分别记载……，当前片段无法确定……” |
| 未提供证据原件 | 只整理文书对证据的提及 | “文书提及……，本次输入未附……” |
| 条件不明 | 不触发依赖该条件的保留、计算或披露动作 | 其他独立有据内容及具体缺项 |
| 主体映射不唯一 | 不合并主体，不输出依赖唯一映射的关系 | 尚能区分的来源陈述 |
| 找不到来源 | 该命题排除；如为核心命题则阻断对应问题 | 来源不足的原因 |
| 输出丢失否定或陈述状态 | 不接受该输出；回退为保留归属和限定语的来源转述 | 通过重新校核的转述 |
| 截断、解析失败、模型输出无效 | 记录技术失败，不把缺失部分写成“无相关事实” | 可读取范围及失败位置 |
| 自动修复仍不满足标准 | 每个输入与规则版本至多一次自动重生成，然后返回部分结果或阻断 | 已通过检查的内容及限制 |

状态为 `partial` 的内容必须带范围说明。某一问题无法确定，不妨碍整理其他独立问题；但不能用部分完成覆盖缺失的关键结论。

## 五、输出验收标准

### 5.1 错误等级及动作

| 等级 | 定义 | 系统动作 |
| --- | --- | --- |
| 阻断 | 破坏关键事实、来源、主体归属、陈述状态，或违反处理限制 | 不将该结果标为完成，不输出相应正式结论或发送内容 |
| 必须改 | 可以定位和自动修正，但当前版本尚不满足任务要求 | 修正并重新执行相关校核；未修正则为部分结果 |
| 建议改 | 不影响事实、任务答案及处理范围的表达问题 | 允许完成，记录可选的表达改进 |
| 可接受 | 有来源且保持任务所需信息和限定 | 通过该项检查 |

“阻断”作用于受影响的结果或发送动作，不删除原始材料、失败记录及可追溯的中间结果。

### 5.2 已确定的错误表

| 错误 | 等级 | 验收要求 |
| --- | --- | --- |
| 引用不存在、引用版本错误或引用没有支持该命题 | 阻断 | 每个实质命题有对应来源；存在来源ID本身不够 |
| 将劳动者、公司、第三人互换或合并 | 阻断 | 主体及关系全程一致 |
| 将“主张”“辩称”写成“法院认定”或无争议事实 | 阻断 | 陈述者及认定层次保持不变 |
| 丢失否定、抗辩或限制条件 | 阻断 | 原有否定和条件不可逆转 |
| 日期金额归错人、款项或程序阶段 | 阻断 | 数值与主体、事项、期间、阶段同时匹配 |
| 由日期冲突直接挑一个作为真实日期，或猜改年份 | 阻断 | 忠实呈现冲突，不猜测 |
| 把证据提及写成原件已提供，或把持有人写成提交人 | 阻断 | 证据存在状态及角色分别保真 |
| 输出直接标识、映射原值或受限内容进入不允许的目标 | 阻断 | 候选与目标用途满足处理规则 |
| 用遗漏全部必要事实的空文本冒充成功摘要 | 阻断 | 必须仍能回答当前任务问题 |
| 遗漏一个与任务直接相关、来源明确的必要事实 | 必须改；遗漏造成含义反转时为阻断 | 补回必要命题，重新执行关系校核 |
| 无依据地增加解释、法律评价或推算 | 阻断 | 本期只整理来源支持的内容 |
| 来源定位不够细，但能够唯一定位且语义有据 | 必须改 | 补足到实际来源块及位置 |
| 重复、句式笨重、非必要的措辞差异 | 建议改 | 不影响事实时不降低法律内容评价 |
| 有原文支持的同义改写、合理并列冲突 | 可接受 | 不要求与参考摘要逐字一致 |
| 与任务无关的信息被省略 | 可接受 | 删除不能损坏其他必要关系 |

### 5.3 计数规则

分别记录以下结果，不合成一个“法律安全总分”：

- 任务状态：计划任务总数，以及完成、部分完成、阻断、技术失败、未运行的数量。任务未运行也保留在总台账中。
- 事实覆盖：在具备固定预期的样本中，应保留事实数与实际保留且正确的事实数。阻断或放弃任务中未产出的必要事实仍计遗漏。
- 来源支持：输出实质命题中得到来源支持的数量。输出为空时该项为“不适用”，不得显示为100%。
- 关系保真：主体、陈述状态、否定、时间金额归属和证据归属分别统计错误数。
- 处理效果：应变换字段、实际变换字段、残留线索和任务效用损失分别记录。

没有真实运行结果时，结果状态为 `not_run`。AI形成的参考答案标为 `reference_origin=ai_authored`，只能作为固定的回归预期，不能据此宣称独立专家评价或真实场景准确率。
