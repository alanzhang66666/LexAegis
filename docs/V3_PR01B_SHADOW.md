# V3 PR-01b 证据范围影子诊断

本阶段参考仓库 PR #5 的 `gate_evidence_scope.py`，只生成当前请求的诊断指纹与现行 G3/G5 收据版本差异，不签发、复用、缓存或认可任何证明。`release_service.status` 的原始 `decision`、正式门禁、签名、一次性许可与网关均保持权威；`scope_diagnostics` 始终 `authoritative=false`、`validated=false`，不得用于审批或外发。

- G3 诊断绑定服务商、用途、接收方、端点、模型和备用槽信息；G5 绑定规则和运行包；G8 绑定本请求、组合风险、累计披露与攻击协议；G9 缺部署身份时无指纹。
- 所有诊断指纹都只是依赖变化提示。空字段、空规则、空攻击协议不得生成指纹；指纹相同也不证明授权、法律适用、签署、效期、撤销、证据字节或隔离。
- G3/G5 只比较同案件、同目的、同接收方、同请求范围内的旧收据版本；忽略其他范围，不返回可复用结论。
- 未来需要独立签署与撤销契约、精确适用范围、角色权限、并发及负向回归、目标环境实测和法学安全评审，才可讨论切换权威检查。此阶段正式外发状态不变。
- 不将敏感原文、身份映射、提示词或实际载荷复制到诊断输出。诊断异常时，仅将该部分标为不可用，保留原判定。

## 范围证明和撤销快照的离线契约实验

`lexaegis/scoped_attestation_shadow.py` 增加部署、服务商和规则包的严格范围模型、Ed25519 签名验证以及独立撤销快照。签发者、公钥、撤销机构、防回滚序号以及已知撤销 ID 集合必须从调用方的可信外部状态取得；缺少撤销快照、签名错误、过期、撤销、回滚、删减已知撤销记录或范围不符均不接受。验签成功只证明对应私钥签过内容，并不证明真实人员身份、签署权限或法律结论。

可选 `ShadowRevocationLedger` 使用本地 Store 的事务锁保存影子快照；新快照必须通过验签、递增序号并保留已有撤销项，私钥不入库。同一个账本实例会记住所见的最高序号和撤销项，实例重启或跨进程仍必须使用独立可信的序号与已撤销 ID 锚点，不能只依赖本地数据库防回滚。此实验不验证证据原件或人员身份，不接 API、放行门禁或真实密钥，也不会传播撤销到生产请求；需要认证密钥管理、独立防回滚锚点、生产撤销传播与法学安全评审后才可讨论实际复用。离线实验依赖可通过 `python -m pip install -e ".[attestation]"` 安装；测试依赖已加入 `requirements-test.lock`。
