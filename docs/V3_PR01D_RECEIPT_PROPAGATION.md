# V3 收据撤销依赖修复

现有正式门禁中的 G1、G2、G3 和 G5 收据可以没有 `request_hash`，但必须绑定精确业务元组与当前版本。旧的 `gate_snapshot.evidence_receipt_ids` 只记录带本请求哈希的收据，因此这些收据撤销后，既有依赖反查可能找不到对应请求。此修复在门禁评估时记录实际通过范围、证据完整性和角色动作检查的收据 ID，包含备槽的有效 G3 收据以及有效隔离收据引用的法学确认。原先请求哈希收据的保守记录逻辑保留。

快照哈希也绑定收据 ID 列表，避免命中结果相同但证明集合变化的两次评估覆盖同一快照。撤销沿用现有事务：待发送的许可被撤销、待处理意图被取消，已 claimed/sending/complete/unknown 的历史保持不变；发送前仍独立重新评估现有正式门禁。

本次不创建跨案件分层证明，也不把离线 Ed25519 实验接入权威放行。修复只在**新生成的快照**中增加依赖；已经生成的旧快照不会自动补齐，因此切换到新版本时须重新评估和重新批准仍未发送的旧请求，或另行设计并验证迁移。快照哈希输入发生变化，既有签发的 grant 不应被当作新快照的授权。当前测试使用合成受控证据、本地 provider stub 和本地网关，不证明真实部署或法律审查。
