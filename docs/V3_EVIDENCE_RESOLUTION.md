# V3 单次评估证据解析去重与备槽原件校验

## 重复计算的处理

原 `evaluate_release` 对每张候选收据调用一次 `resolve_evidence`，后者每次扫描并核验同组文件。现在以精确接收方 tuple、request_hash 和 bound_versions 分组，在一次 `evaluate_release` 调用中解析一次并按收据 ID 索引。所有 G0–G10 条件、原件哈希、签署动作、材料/规则/身份/请求绑定及一次许可仍成立；没有把未命中或异常当通过。

该局部缓存不持久化、不跨评估、不跨事务，也不跨审批/排队/发送阶段。每个新评估重新读证据；组解析失败在当前评估中失败关闭，不靠逐张重复重试变成通过。时间以本次解析时刻为准；签发许可仍执行现有即时校验，未延长证明有效期。

## 同时补齐的备槽缺口

旧备槽 G3 路径只做收据元数据、manifest 和具名动作校验，未通过相同的受控 EvidenceIntake 读取原件。现在备槽按自己的精确接收方/版本/请求范围解析，只有原件完整性通过的法03/法04 收据才参与判定。主槽证明不借给备槽，备槽缺失、篡改、过期或解析异常均阻断。

`issue_grant` 另外重验备槽当前 G3 元数据、完整签署组合、版本、有效期、撤销和具名角色动作，避免评估后发生变化仍签发许可。此项是新增的拒绝保护，不取消任何现有主槽或网关检查。

## 实测与范围

同一合成、主槽单接收方案例：旧实现 resolver_calls=10、artifact_reads=70；新实现 resolver_calls=2、artifact_reads=14。下一次评估再执行 2 次解析和 14 次读取，不使用上一轮结果。这个 80% 是该用例的调用/读取次数减少，不是网络延迟或生产 p95 提升。双接收方用例独立解析备槽，共 3 个精确组。

修复前，新增 5 个回归测试全部失败，证实重复读取以及备槽原件篡改/删除未被评估拒绝；修复后这些测试通过。另覆盖备槽有效许可正例、评估后撤销/过期/换 scope/换版本/移除角色动作/manifest 变化拒绝、解析错误失败关闭和后续评估不复用旧结果。

所有证据、签署者和服务商档案为合成测试数据。这里不是跨案件权威准入证明复用，不引入可信签发服务、外部撤销锚或新的授权来源；也未完成审批函数内部两次完整评估的合并。真实云、目标环境、法学/安全签发、动态能力与 A/B 双链验收仍独立进行。没有改草稿包的发布状态或开启外发。
